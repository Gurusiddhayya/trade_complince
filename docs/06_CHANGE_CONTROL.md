# Change Control

The current V2.3 scope is the baseline.

Future requirements should be classified as:
- **Regulatory change:** new/changed rule or official source.
- **Defect:** behavior that violates the approved baseline.
- **Clarification:** wording/UX change without scope expansion.
- **Enhancement:** new capability or product behavior.
- **Integration:** new external system/authority connection.

Each change should record:
1. Requirement.
2. Reason/source.
3. Affected product(s).
4. Regulatory impact.
5. Data-model impact.
6. API/UI impact.
7. Security/privacy impact.
8. Test cases.
9. Version/effective date.
10. Approval and release note.

No new feature should be added solely to increase a version number.
